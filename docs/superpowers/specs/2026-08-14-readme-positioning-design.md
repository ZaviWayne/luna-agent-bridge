# README 项目定位重写设计

## 目标

让新用户在阅读 README 开头约 30 秒内理解三个问题：为什么需要这个项目、自己是否需要它、应该使用哪条安装路径。

## 核心定位

项目首先解决可控的子 Agent 模型路由问题：主 Agent 可以继续使用高能力模型，而适合拆分的边界清晰任务可以路由到 `gpt-5.6-luna`，以便在质量、延迟和成本之间做选择。`max` 是推理强度，不是独立模型；README 不承诺固定节省比例，并说明实际效果取决于任务、账号和运行环境。

跨会话队列、恢复和接管是外部 Bridge 提供的增强能力，不应取代模型路由这一首要动机，也不应被描述为 Codex 官方原生能力。

## 信息结构

1. 标题下的一句话定位，直接说明模型路由、成本权衡和可选持久化。
2. 一个简短场景，说明高能力主 Agent 与低成本子任务模型之间的分工。
3. 原生 Skill 与外部 Bridge 的决策表，帮助用户选择路径。
4. Bridge 能力与明确不承诺的内容，包括模型可用性、侧边栏显示和生命周期。
5. 分路径快速开始：原生 Skill 配置和外部 Bridge 安装。
6. 项目结构、安全边界、测试和许可证信息。

## 元数据同步

将 `pyproject.toml` 的 `description` 改为具体说明模型路由、GPT-5.6 Luna 和可选跨会话持久化，避免使用无法体现项目价值的泛化描述。

## 验收标准

- README 首屏明确写出项目动机，而不是从目录或安装命令开始。
- 明确区分 `gpt-5.6-luna`（模型）和 `max`（推理强度）。
- 不把成本节省、模型可用性或跨会话恢复写成无条件保证。
- 保留原生 Skill 优先和外部 Bridge 可选的安全边界。
- 公开文档不包含本机绝对路径、开发计划或生成目录。
